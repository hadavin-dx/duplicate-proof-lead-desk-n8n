# What is original, what is new, and the history of this folder

(Moved out of `README.md`. Terms are explained in `GLOSSARY.md`.)

* **Original scripts** (the ones that produced the 2026-11-09 numbers): `fakes2.py`, `lib.py`, `api.py`, `mkwf2.py`, `mkwf3.py`, `deploy2.py`, `deploy3.py`, `g12.py`, `g3.py`, `g12e.py`, `g3e.py`. They are not reformatted. Changes made after an outside read of this folder (polling instead of fixed waits, attempt accounting, kill validity, return codes, fresh result files, own PIDs only, minimal environment, load samples, Linux support, polling of the real webhooks, the idle check, `run_manifest.json`, one set of kill counts, per-execution times in the raw rows, one list of lost-connection names, clean stop on SIGTERM/SIGHUP, image pull with retries) changed `lib.py`, `g12.py`, `g3.py`, `g3e.py`, `g12e.py` and the new files. They change how the waits and the counting work, so a rerun is a different measurement procedure from the 2026-11-09 one: compare the tables, not the timing.
* `CHANGES-FROM-ORIGINAL.diff` shows the first batch of those changes only (it is a generated file: a note at its top says so); the later ones are in git history. The changes in that file are: secrets and ids that were literals are now generated or read at run time, the Git-bash wrapper and absolute paths are replaced by arguments, and the Docker container name is a setting.
* **New code, not in the 2026-11-09 run:** `setup.py` (first-start owner account, Postgres credential, tables), `deploy_b.py` (**variant b's deploy is new**: the original deploy script had no branch for b, so a rerun of b exercises new code), `run_all.py` (replaces three run-order scripts), `summarise.py`, `sums.py`, `cleanup.py` (stops what a hard-killed run left: ends a recorded process only if it started in this work folder and leads its own process group, and is the recorded program: node or python), `build_workflows.py`.
* **Raw results** in `published_run/` are the files of that run with the time of day removed (the date is kept) and the n8n workflow id inside the retry replies replaced by `<id>`. No count was edited.
* **`SHA256SUMS`** lists the hash of every file in `published_run/`, the workflows, `tables.md`, the lock and package files, the rule texts (`GATES.md`, `REPRODUCTION-RULE.md`) and the explanatory files `GLOSSARY.md`, `DETAILS.md` and `CHANGES.md`. It does **not** list `README.md`, the licence, the diff or any harness code (`gate-rule.sha256.txt` is listed but names a file that is not in this folder). `python3 -B -I demo_only/n8n_evidence/harness/sums.py check` therefore confirms that those files are the ones listed; it cannot detect a changed `SHA256SUMS` or changed harness code. The test `tests/test_n8n_evidence.py` in the repository's `tests/` folder checks the hashes and regenerates `tables.md` from the raw files.
* **History of the explanatory files.** Several outside reads (cold readers who saw only these files) each found gaps; the files were edited after each. In the last edit the README was cut to a short front page and its detail moved into `GLOSSARY.md`, `DETAILS.md` and this file (moved, with the exceptions listed at the top of `DETAILS.md`), the earlier wording, which called the retry and HTTP 500 results a property of the test workflows and not of n8n, was replaced by "the cause was not investigated" because the cause is unknown, the README's statement of rule R1 was made identical to the rule file's, and the G3 position of variant a was stated in full.
* **To add to the public repository's `.gitignore`** (that file is not in this folder): `.dev-folder`, the one-line file that lets a developer point the tests at another copy of the folder; it must never be committed.
