# The portal

Two words to keep apart: the **lead stage** shown in the portal (New, Contacted and so on) is the stage of a lead, from the lead flow file (`DESK_LEADFLOW_FILE`) and is not a stage of any deployment.

Open http://127.0.0.1:8765/ui/ in a browser while the desk runs. It shows the desk's records on these pages: **Overview** (a summary that adds up: every received request is counted once, as New, Repeat, Request to check or Not decided yet), **Leads** (the leads, with a "Hide names and email addresses" switch that only changes the display: lead names, email addresses, phone numbers and messages are masked on screen by default, and the switch, remembered for that browser tab's session only, turns the masking off to see them and to search by name or address; while they are masked the search does not match names or address text (only the company and the lead number; request numbers are not searched while masked), and a small eye button beside a masked value shows that one value for up to 30 seconds without turning the name or address search on. The JSON replies still carry the values, so a person with the browser's developer tools can read them, and the desk's logs never hold them), **Needs a person** (incomplete requests, and follow-ups that failed or whose outcome is unknown; tabs for items that are only waiting and for information), **Request log** and **Data and AI** (what the desk stores and what the AI step receives); a lead's side panel shows a "Next step:" line for a failed or unknown follow-up and lists the lead's later messages: each new request from the same email address, when it came, how long after the first one, and what it says differently.

When every kind is a stand-in (no real CRM, no real mail sender, no live AI step) but the demo tools are not installed, a banner reads "Every lead is demo data. The demo CRM and demo mail are not connected. Nothing here is sent to real customers or real systems."

When any real service is connected, a warm-coloured banner reads "Real services are connected" and names them (CRM, mail, AI step); the demo tools are then not loaded at all.

The pages read the desk's records through a second, read-only database connection (a write through it fails, and one test shows that); the buttons that retry or resolve an item call the same `/review` routes as everything else.

While the desk does not answer, or answers with a problem, the pages keep showing the last values and the Retry and "I checked" buttons are switched off, with the line "Actions are paused until the desk answers."; they work again when the desk answers. The buttons pause when any request fails to reach the desk, or when the summary or the review list answers with a server error; a server error on another page's own request does not pause them. The page cannot tell a stopped desk from a lost network connection, so both show the same notice.

In the Leads list and the Request log, the follow-up column shows the email state only; a lead whose CRM entry is unclear shows "Waiting for the CRM check" and a second chip, "CRM not confirmed".

**What writes:** the pages and every `GET /api/ui/...` answer only read. The Retry button and the answer buttons ("I checked: it was sent" and "I checked: it was not sent" on a follow-up card; "The CRM entry is there" and "The CRM entry is not there" on a CRM card) write, through `POST /review/...`; a wrong "not sent" answer can cause a second email on a blind mail system.

When the demo extension is loaded (only when every kind is a stand-in, which is the default), `POST /api/demo/crash` and `POST /api/demo/burst` also write (they stop the desk on purpose and send test requests); they have no login either.

Every request, including the pages, must come with a `Host` header that names this computer (or a name from `DESK_ALLOWED_HOSTS`), and a request from a page on another address is refused with 403 before anything is read. The exact routes are in `contract.md`.

**What the Host and Origin check does and does not do.** It stops web pages in a browser: a page on another web site, and a web site that tricks the browser into talking to this computer under another name ("DNS rebinding"). It does NOT stop a person or program that can reach the desk's address and sends the right `Host` header by hand. There is no login. So keep the desk on `127.0.0.1` (the default). If a container (n8n in Docker, for example) must reach it, bind to the one address that only your container network reaches (the Docker bridge or host address), never to the all-zeros address (every network interface). This is possible only while every kind is a stand-in: with any real service the desk refuses every bind that is not a loopback address. A bind to any other address than this computer's own exposes every lead (names, e-mail addresses, phone numbers, messages) to everyone who can connect, and the desk prints a warning at start-up when you do that. Close the portal while you run a load test: every open page asks the desk for its numbers every few seconds.
